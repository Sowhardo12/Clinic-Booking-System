# AGENTS.md — Delta Clinic Booking System

## Project Overview

The Delta Clinic Booking System is a NestJS (v10) + TypeScript (v5) clinic appointment booking backend designed as a **naive baseline** for identifying and fixing concurrency and performance problems with measurable results. It models a clinic with branches, doctors, appointment slots, patient bookings, payments, and idempotency keys. Load tests (k6) and query-plan analysis (`EXPLAIN ANALYZE`) are used to quantify the impact of each fix.

## Code Style & Architectural Patterns

### NestJS Module Structure

- Each feature module (`appointments`, `branches`, `admin`) has its own `controller.ts`, `service.ts`, `repository.ts`, and `dto/` folder.
- Modules are registered in `app.module.ts` via the `@Module({ imports: [] })` decorator.
- Global `ValidationPipe` is bootstrapped in `main.ts` with `whitelist: true, transform: true`.

### Repository Pattern with Transaction Support

```typescript
// Repository runs SQL via an optional client (for transaction safety)
private run(sql: string, params: any[], client?: PoolClient) {
  return client ? client.query(sql, params) : this.db.query(sql, params);
}

// Example: find slot with FOR UPDATE lock inside BEGIN...COMMIT
async findSlotByIdForUpdate(client: PoolClient, slotId: number) {
  const r = await client.query('SELECT * FROM appointment_slots WHERE id = $1 FOR UPDATE', [slotId]);
  return r.rows[0];
}
```

### Transaction Flow (bookAppointment)

```typescript
await client.query('BEGIN');
// 1. Lock slot row
const slot = await this.appointmentsRepo.findSlotByIdForUpdate(client, slotId);
// 2. Check availability, reserve, process payment, confirm booking
await client.query('COMMIT');
```

### Idempotency Key Pattern

- Client sends `Idempotency-Key` header
- Server stores key in `idempotency_keys` table with status `processing` → `completed`/`failed`
- Duplicate request with same key returns cached response

### Redis Caching (BranchesService)

- `cache:branches:all` — branch list, TTL 60s
- `cache:branch:{id}:doctors` — doctors per branch, TTL 60s
- Slot data is **not** cached (always hits the database)

### N+1 vs Optimized Comparison (AdminService)

- **N+1:** 1 initial query + N individual queries in a loop — logged with `totalQueriesExecuted` and `executionTimeMs`
- **Optimized:** Single `JOIN` across relevant tables — typically 90%+ query reduction

## Boundaries & Guardrails

### Always Do (safe actions without confirmation)

- Read and inspect existing source files, DTOs, controllers, services, and repositories.
- Create new files like `docs/API.md`, `project_info.md`, or `AGENTS.md` itself.
- Run `npm install`, `npm run build`, `npm run format`.
- Run k6 load tests: `k6 run ./k6/contention-test.js` and `k6 run ./k6/throughput-test.js`.
- Inspect database data with `docker exec -it ... psql ...`.
- Check Redis keys: `docker exec -it delta_redis redis-cli keys "*"`.
- Add or update environment variables in `.env` (non-destructive).
- Create migration files in `src/database/migrations/`.

### Ask First (requires human sign-off)

- **Destructive database operations:** Running `seed.ts` truncates 9 tables — confirm before running in production-like environments.
- **Schema migrations:** Adding/Dropping columns or tables via raw SQL — verify data impact first.
- **Docker service management:** `docker compose up/down` — confirm intent, especially with volume mounts (`pgdata`).
- **Deploying to production** or changing ports/hosts in infrastructure.
- **Modifying the `prometheus.yml`** configuration — verify it won't break observability dashboards.
- **Altering the connection pool size** (`DB_POOL_MAX`) — understand performance implications.

### Never Do (strict constraints)

- **Modify source code** to "fix" behavior without quantitative backing — this project is designed to measure before/after.
- **Delete or rename** `schema.sql`, `seed.ts`, `docker-compose.yml`, `package.json`, or any file listed in `.gitignore` without replacement.
- **Override the global ValidationPipe** configuration unless replacing with a custom pipe — documented in `main.ts`.
- **Hardcode port numbers** in new code — always use `process.env.PORT` (the project uses 13000 in runtime, but docs and k6 scripts reference 7333/3000 — align to env var).
- **Ignore the `FOR UPDATE` contract** — row locking must always occur inside a `BEGIN...COMMIT` block; outside one the lock is released immediately.
- **Add new npm dependencies** without reviewing the existing stack first — the project already uses `@nestjs`, `pg`, `ioredis`, `prom-client`, `class-validator`, `class-transformer`.
- **Run `TRUNCATE` on production data** without a full backup and confirmation.
